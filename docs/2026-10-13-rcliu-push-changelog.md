## 1. 模型响应读取与本地启动

- `ResponsesApi` 同步调用改为通过 `exchange` 直接读取完整响应流，再解析 JSON，避免响应探测与 Brotli 解压组合导致内容提前结束、出现 `JsonEOFException`。
- 读取响应前显式使用原有错误处理器，保留 HTTP 错误分类；日志记录 HTTP 状态和读取字节数，解析失败保留长度信息。
- 增加压缩响应、HTTP 错误及异常响应等针对性测试。
- 新增 `.run/DataAgent Backend Logs.run.xml` 和 `.run/DataAgent Frontend Logs.run.xml`，分别配置后端 8065、前端 3001 的 IDEA 启动及控制台日志保存。
- 移除默认配置中指向缺失 `elasticsearch/http_ca.crt` 的 SSL bundle 配置，避免当前远程连接配置因缺失本地证书无法启动。这不是关闭所有 HTTPS 校验；需要自定义 CA 的环境仍须配置相应信任证书。

IDEA 配置中的 Node 路径和 Docker socket 为本机路径，同事使用时需要替换。运行日志不包含在本次推送中。

## 2. 喷涂缺陷统计与查询结果一致性

- 新增 `PaintDefectAnalysis`，对模板覆盖且工厂、时间范围明确的喷涂缺陷问题，使用受控 SQL 聚合及确定性报告生成。
- 按完整缺陷明细的 `SUM(defect_count)` 统计，区分缺陷数量、记录条数和去重不良产品件数，不把三者混用。
- 支持指定大类、父类内具体缺陷、排除条件及 Top1 至 Top50；排名筛选范围和占比分母分别处理。
- 分母区分全部缺陷、当前父类范围、所选分类与 TopN 自身，保留原始分类数量、分母和来源信息。
- `TableRelationNode` 对受控请求保留已召回的必需明细及字典表，避免精细选表漏表导致分类统计退化为总计。
- `FeasibilityAssessmentNode` 和 `PlannerNode` 对受控模板请求减少不必要的澄清与额外计算，采用一次 SQL 快照直接生成报告，避免后续 Python 重试覆盖数据来源。
- `SqlExecuteNode` 将实际执行成功的 SQL 写回计划，并在结果中保留对应查询步骤，便于下游准确引用。
- `ResultSetBuilder` 保留 SQL NULL，并标记结果截断及行数上限，避免把缺失值或截断结果误当作完整数据。
- 新增 `PythonResultValidator`，针对已覆盖的 SUM 别名丢失矛盾进行校验，避免有效聚合值被误写为空；不凭空补值。

## 3. 多轮改图与多图引用

- 明确的纯图形修改复用原结果；明确改变日期、筛选或数据范围时重新查询，避免展示快捷路径吞掉新的范围。
- 占比转换只有在原始数量和所需分母可验证时本地执行；缺少所需分母时进入查询或澄清路径。
- 对已验证的全量分母，TopN 数量图转完整构成饼图时补充“其他缺陷”，不把 TopN 合计冒充全部。
- 用户明确要求所选分类或 TopN 自身占比时，才使用对应自身合计作为分母。
- 将明确指定的分母范围通过结构化请求传入图执行状态，避免自然语言增强改写后丢失。
- 按用户指定顺序生成多张图；编号或名称明确时定位对应图，含糊的多图修改要求澄清。
- 同一报告已有实际 CHART 工件时，不再把中间查询结果的展示配置当成额外图表，修复“实际一张图却识别为多张”的问题。
- 坐标轴修改合并已有上下限后校验，拒绝下限大于上限，保留原图。

这些规则依赖已验证的来源和分类元数据，并未实现任意业务指标的重叠关系自动识别。不能根据字段名称证明任意指标互斥。

## 4. 报告改写、澄清与停止操作

- 新增 `ReportFactsProtector`，报告精简或风格改写时保护含数字段落、表格及代码块；校验模型返回的标记和新增数字，违规改写不发布。
- 新会话缺少年份、非法日期等已覆盖情况直接澄清；明确的未来日期记录数请求可以查询，无记录不被解释为实际没有不良。
- 具体缺陷在指定父类范围内未出现时说明未查到匹配明细，不用父类合计代替该具体缺陷数量。
- 新增 `ConversationExecutionRegistry`，从提交阶段登记执行，支持按会话取消；规划结果晚到时不继续启动图执行。
- 停止图执行时发送终止事件并清理，避免心跳连接继续等待；验证停止后同会话可再次提问。

取消登记限当前进程。这里验证的是应用任务终止及会话恢复，不代表所有 JDBC、远程模型请求或 Docker 作业都能立即被物理中断。
